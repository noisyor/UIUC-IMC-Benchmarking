Methodology

A common frame for diverse IMCs.

The benchmarking method separates architectural structure, comparable metrics, and interpretation. This avoids treating precision-normalized values or bank-level results as complete system claims.

Compositional view

Follow one computation through the architecture.

An IMC is organized into canonical stages so that reported designs can be described using the same coordinates.

STAGE 01

Activation mapper

Encodes input activations in time, voltage, or current before they enter the memory array.

STAGE 02

Bitcell array

Defines the compute model, bitcell organization, row and column parallelism, and physical array dimensions.

STAGE 03

ADC column

Acts as the canonical unit: one ADC and the rows and columns contributing to its dot product each read cycle.

STAGE 04

Output composer

Combines ADC outputs and, for multi-bit weights, realizes powers-of-two summation before or after conversion.

Metric set

Normalize the arithmetic, retain the context.

The project uses bit-normalized figures of merit to compare designs with different operand precisions. Raw architectural fields remain available so each normalization can be audited.

MetricMeaningWhy it matters
1b-TOPSBit-normalized throughputPlaces different input and weight precisions on a shared operation basis.
1b-TOPS/WBit-normalized energy efficiencySupports energy comparison while preserving operand-precision fields for audit.
1b-TOPS/mm²Bit-normalized compute densityConnects throughput to reported or estimated bank area.
BI(col)Information at the ADC-column inputCaptures the precision and dimension of the computation feeding one ADC.
SNRcolADC-column compute signal-to-noise ratioMeasures deviation from a fixed-point digital reference, including noise and distortion.
NcoreNumber of IMC banks/coresDistinguishes bank-level performance from processor-level scale-up.

Accuracy gap

Efficiency needs an accuracy coordinate.

Analog IMCs trade compute fidelity against energy. The associated papers therefore argue that efficiency, throughput, and accuracy should be reported together, with compute SNR at the ADC-column or bank level and statistical confidence for network-level accuracy.

The database exposes reported ADC precision and pre-ADC information content as a proxy when compute SNR is unavailable. This is diagnostic evidence, not a substitute for direct accuracy measurement.

Analysis protocol

Six checks before comparison.

01

Normalize precision

Convert reported throughput and efficiency to a one-bit operation basis.

02

Resolve the ADC column

Extract dot-product dimension, physical parallelism, precisions, and converter context.

03

Recompute throughput

Use latency and physical parallelism to cross-check the reported value.

04

Cross-check efficiency

Normalize recomputed throughput by total reported power when it is available.

05

Verify density

Normalize throughput by bank area, estimating area from die imagery only when needed.

06

Preserve level

Keep bank and processor results distinct so scale-up overhead is not hidden.
